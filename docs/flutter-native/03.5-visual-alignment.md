# Slice 3.5: visual alignment with the PWA

## Outcome

Make the Flutter app look like the PWA. Build the FORM design system in Flutter
and restyle every screen delivered by Slices 1 to 3 so it matches its PWA
counterpart on the same phone.

Read [`stage-1-spec.md`](stage-1-spec.md), especially "Visual parity". This slice
owns every `V` item in [`parity-checklist.md`](parity-checklist.md).

## Dependencies

Slices 1 to 3 are complete. Behavior, state, and data flow stay unchanged. This
slice changes presentation only.

## Ownership

Primary code lives in:

- `apps/mobile/lib/app/form_theme.dart` and FORM design tokens
- shared FORM components in `apps/mobile/lib/widgets`
- presentation code in `features/feed`, `features/wardrobe`, `features/intake`,
  and `features/settings` as far as those screens exist today
- bundled fonts or icon assets when the PWA's look requires them

## Visual source

`apps/web/public/style.css` and the markup rendered by `app.js` at phone width
define the target. Start from the `:root` tokens:

- colors: paper `#f6f5f1`, ink `#242923`, green `#344d3f`, muted `#777b72`,
  line `#e2e4dc`, card chrome `#e9e8dc`, white surfaces, category and occasion
  tints
- typography: system sans for UI, `ui-serif, Georgia, serif` for display text,
  and the PWA's sizes, weights, letter spacing, and tabular numerals
- shapes: 12px inputs, 25px sheet corners, and the PWA's card, chip, and button
  radii
- motion: the `--pop` and `--ease-out` curves and their durations

## Work

1. Extract the PWA tokens into one Dart source for colors, text styles, spacing,
   radii, and curves. Pick a serif that renders like `ui-serif` on iOS and
   bundle it if the system cannot provide it on both platforms.
2. Replace Material's default look in the theme: no ripples, no elevation or
   surface tint, no tonal M3 colors. Keep native page transitions, back-swipe,
   scroll physics, keyboards, and system pickers.
3. Build the shared FORM components the existing screens need: tab bar, page
   header, buttons, filter chips, search field, text inputs, image cards, empty
   and error states, bottom sheets, and confirmation dialogs. Build each one
   against its PWA counterpart.
4. Restyle the shell and the foundation access states.
5. Restyle Wardrobe: grid, filters, search, counts, empty states, item detail,
   editing, catalog-image generation, version history, and archive.
6. Restyle Intake: capture entry, drafts, upload progress, detection boxes with
   category tints, proposal selection, manual path, and discard.
7. Compare every restyled screen and state with the PWA in a screenshot pair at
   the same phone width. Fix differences or record them as intended deviations.
8. Write [`visual-guide.md`](visual-guide.md): the token source, the component
   list with their PWA selectors, and the comparison routine that later slices
   reuse.

## Verification

The spec excludes golden and widget tests, so visual parity is checked by
screenshot pairs and Nico's review on device. Keep screenshots out of Git.
`fvm flutter analyze` and `fvm flutter test` must still pass.

## Completion criteria

- Every `V` checklist item is checked.
- No existing screen shows Material's default visual language.
- Each existing screen has a PWA screenshot pair with no unexplained difference.
- `visual-guide.md` exists and later slices can follow it without rereading the
  CSS from scratch.
- Behavior and unit tests are unchanged.

## Exclusions

Dark mode, tablet layouts, and landscape stay outside Stage 1. Screens that
Slices 4 to 6 introduce are styled in their own slice using the components built
here.
